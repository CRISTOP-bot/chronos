Features

Everything you need to understand what happened

CHRONOS combines low-level tracing with high-level analysis tools.

Real ptrace Recording

Captures every syscall (enter + exit), process/thread lifecycle and memory maps using Linux ptrace. No instrumentation needed.

Temporal Checkpoints

Automatic memory snapshots every 10 syscalls — full region capture with bytes, permissions and names. Compare any two points in time.

State Reconstruction

Replay variable changes forward to any event index. Diff two moments to see exactly what changed — added, removed, and mutated variables.

Memory Explorer

Browse captured memory regions with hex dump viewer, ASCII preview and string extraction with filter. Inspect any checkpoint at byte level.

Binary Format v2

Custom .chronos format with zstd-compressed events, CRC32 integrity, section offsets and versioned header. Fast to read, small on disk.

Qt6 Desktop GUI

Dark technical interface with visual timeline ruler, color-coded event table, inspector panel, memory viewer, execution graph and state diff.

MCP Server

13 tools exposed over stdio JSON-RPC so AI assistants can trace, search, reconstruct and export recordings without leaving their context.

HTML & JSON Export

Export any recording to a self-contained HTML report or structured JSON for further analysis. Branch recordings for parallel investigation.

Analytical Branches

Fork a recording at any point to create independent investigation branches. Each branch is a full .chronos file with its own event log.

How it works

From execution to insight

Three steps to understand any program's behavior.

01

Record

CHRONOS forks the target binary and attaches with ptrace(PTRACE_TRACEME). Every syscall enter/exit is captured with arguments and return values. Every 10 syscalls, full memory regions are snapshotted into a checkpoint.

# Trace any ELF binary
chronos_cli trace /usr/bin/curl recording.chronos

Traced 2847 events → recording.chronos
5 checkpoints · 18 unique syscalls
02

Navigate

Load the recording in the GUI or query it with the CLI. Jump forward/backward through the event timeline, jump between checkpoints, search for any syscall name, variable or function by text.

# Search for write syscalls
chronos_cli search recording.chronos write

matches=3
  78 SyscallEnter · write
  79 SyscallExit  · write → 0x1
  81 SyscallEnter · write
03

Reconstruct

Diff memory between any two checkpoints to see exactly which regions changed, how many bytes differ, and what new regions appeared. Reconstruct variable state at any event index and compare two moments.

# Compare first vs last checkpoint
chronos_cli memdiff recording.chronos 1 5

changed 0x5606fcc1c000: 364 bytes differ
added   0x7fc024387000 (8192 bytes)
removed 0x7fc02433a000 (8192 bytes)
CLI Reference

Every command at a glance

All commands read and write the .chronos binary format.

CommandDescription
trace <bin> [out]Trace a binary with ptrace, save recording
info <rec>Show recording stats — events, checkpoints, types
search <rec> <text>Search events by name, syscall, variable or detail
checkpoints <rec>List all checkpoints with IDs and region counts
memdiff <rec> <a> <b>Compare memory between two checkpoint IDs
reconstruct <rec> <id>Reconstruct memory map from a checkpoint
strings <rec> <id> [filter]Extract readable strings from a checkpoint
state <rec> <idx>Reconstruct variable state at event index
stats <rec>Execution metrics — events/sec, syscall counts, entropy
maps <pid>Read live /proc/<pid>/maps
branch <src> <dst> <label>Fork a recording into a new investigation branch
export-html <rec> <out>Export self-contained HTML report
export-json <rec> <out>Export recording to structured JSON
project-create <dir> <name>Create a project with multiple recordings
project-add <project.json> <rec>Add a recording to a project
project-info <project.json>List recordings in a project
demo [out]Write a demo recording and reopen it
MCP

AI-native tooling

CHRONOS ships a Model Context Protocol server so AI assistants can use it as a tool.

Start the MCP server with a single command. Any MCP-compatible client (Kiro, Claude Desktop, OpenCode…) can then trace binaries, search recordings and reconstruct memory without leaving the conversation.

# Launch the MCP server
./mcp.sh /path/to/chronos_cli

# Or set CHRONOS_CLI and run directly
export CHRONOS_CLI=./build/tools/chronos_cli
python3 mcp/mcp_server.py

Add it to your MCP config:

{
  "mcpServers": {
    "chronos": {
      "command": "/path/to/chronos/mcp.sh",
      "args": ["/path/to/chronos_cli"]
    }
  }
}

Quick Start

Up and running in minutes

1

Clone

git clone https://github.com/CRISTOP-bot/chronos.git
cd chronos
→
2

Build

cmake -S . -B build \
  -DCHRONOS_BUILD_GUI=ON
cmake --build build -j$(nproc)
→
3

Trace

./build/tools/chronos_cli \
  trace /bin/ls out.chronos
./build/gui/chronos_gui out.chronos
Dependencies: CMake 3.20+ GCC/Clang C++20 zstd zlib Qt6 Widgets (GUI only) GoogleTest (tests)
